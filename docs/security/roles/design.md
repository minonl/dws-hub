# 角色：design（设计验收）

**目标**：陌生人能读得懂、用得对；CLI 行为一致；没有内部黑话。

## 清单

1. 信息层级：README 顺序 = 是什么 → 为什么 → 安装 → 快速开始 → 配置 → 边界 → 许可。
2. 文档不重复冲突：README 与 `skills/dws-hub/SKILL.md` 对同一命令的描述是否一致（尤其 dry-run、退出码）。
3. CLI：`--help` 是否列全可用子命令；未实现的命令不能出现在 help 里（或必须标「迁移中」）。
4. 退出码：README / SKILL / 代码中的退出码含义是否一致（0/2/3/4/5）。
5. 错误信息：只含通用路径（`$DWS_HUB_HOME`），不得出现真实用户名路径。
6. 术语：`consumer / follow / anchor / topic / ext_id / scope` 是否在文档中有简短定义，且用法一致。
7. 语言边界：规则见 `docs/security/public-release.md` 的「语言边界」一条（唯一来源）；本文件不复述。
8. 内部黑话：不得出现内部规则编号、内部流程代号、内部 agent 名。
9. 可访问性细节：代码块可直接复制；表格不超宽；链接有效（相对路径存在）。

## 判定

- P0：help 列了不存在的命令 / 文档教用户做危险操作（如默认真发）
- P1：退出码或安全默认描述错误
- P2：术语不一致、链接失效
- P3：排版

## 输出

JSON 契约，`role: "design"`。
